# 07 · 前端设计（Vue3）

> Vue 3.4 + TypeScript + Vite 5 + Vue Router 4 + Pinia 2 + Element Plus 2.7 + axios + 高德 JS SDK
> 三端同仓：`student-web` / `rider-web` / `admin-web`（共用 `shared`，pnpm workspace）
> 版本 v1.2：幂等键按"用户动作"生成、WS 改 `/topic` + CONNECT 头鉴权、补消息中心与模拟收银台、MinIO 预签名、状态筛选映射、去掉"token 自动续期"的虚假承诺。

---

## 1. 工程结构

```
frontend/
├── pnpm-workspace.yaml
├── shared/                     # 三端共用
│   ├── api/http.ts             # axios 实例：token、trace_id、错误码、幂等键
│   ├── api/modules/            # auth / order / rider / admin / agent / common / message
│   ├── components/             # 通用组件
│   ├── composables/            # useWebSocket / useLocation / useCountdown / useIdemKey
│   ├── types/                  # 与 03 文档一致的 TS 类型
│   └── styles/                 # 变量、主题
├── student-web/
├── rider-web/
├── admin-web/
└── nginx.conf                  # /student /rider /admin 三个 location
```

**为什么单仓**：简历项目好维护；目录强制隔离，`shared` 只放无状态逻辑。

## 2. 通用约定

### 2.1 请求封装（`shared/api/http.ts`）

| 能力 | 约定 |
|---|---|
| baseURL | 三端都用 `/api`（Nginx 按路径转发到 Java） |
| token | `localStorage` 按端隔离：`cr_student_token` / `cr_rider_token` / `cr_admin_token` |
| traceId | 每次请求生成 32 位 hex（`crypto.randomUUID().replace(/-/g,'')`）作为 `X-Trace-Id`；响应带回则存 store |
| 统一响应 | `{code, message, data, trace_id}`；`code!==0` 抛业务异常 |
| 错误码分支 | `401xx` → 清 token 跳登录；`50002/50004/50005` → 弹"智能助手不可用"并切表单；`42901` → 退避重试 1 次；`40303` → 提示无权限并记日志 |
| **幂等键** | **不要在拦截器里生成**。由用户动作触发时调用 `useIdemKey().get(actionKey)`：首次生成、重试复用、成功后 `clear()`；下单/确认/改派/加价/退款五类必须带 |
| 文件访问 | 上传返回预签名 `url` + `expires_at`；图片加载失败（过期）时重新向后端换取 URL |
| 时间 | 统一 dayjs 解析 ISO8601 带时区，展示 `MM-DD HH:mm` |

### 2.2 WebSocket 封装（`useWebSocket.ts`）

- 连接 `/ws`，STOMP over SockJS；**token 放在 CONNECT 帧的 `Authorization: Bearer <jwt>` 头**，不放 query。
- 订阅 `/topic/order/{userId}`、`/topic/rider/{riderId}/task` 等；订阅前确认 userId 来自登录态。
- 断线重连：1s/2s/4s/8s/16s，最多 5 次；重连成功触发 `onReconnect` → 页面拉一次全量。
- 心跳：每 30s 发一次（服务端 60s 未收即断）。
- 收到 `401`/订阅被拒 → 清 token 跳登录。

### 2.3 视觉规范（三端统一但有区分）

| 项 | 学生端 | 骑手端 | 运营端 |
|---|---|---|---|
| 主色 | `#2F6BFF`（蓝） | `#FF7A1A`（橙） | `#1F2937`（深灰） |
| 强调 | 圆角 12px、卡片阴影 | 大按钮（≥48px 高） | 密集表格、无圆角 |
| 字号 | 正文 15px | 正文 17px（户外可读） | 正文 13px |
| 布局 | 单列卡片流 | 底部固定操作栏 | 左导航 + 右内容 |

> 不用紫色系。三端同色系会让人分不清角色。

## 6. 关键交互设计

### 6.1 学生端首页：三个入口并列
立即下单（最稳）/ 智能下单（最有趣）/ 我的订单（最多用）。**不要一进来就弹 Agent 对话框**。

### 6.2 骑手大厅：抢单必须有明确失败反馈
toast + 卡片置灰，文案具体：
- "手慢了，这单被抢走了"（40902）
- "你手上已有 3 单，先送完再抢"（40903）
- "你还没上线 / 资质未通过 / 信用分不足"（40906）
- **抢单成功后不要立即跳详情**：等 100ms 或收到 WS `ACCEPTED` 再跳，避免同步落库瞬间的竞态（v1.2 同步落库后通常无需等待，但保留兜底）。

### 6.3 报价卡：只允许一个主按钮
`确认下单` 是唯一主按钮（带 `draft_id` 调 U-08）；`改条件` 是次要文字按钮。支付永远跳标准收银台。

### 6.4 工单详情（运营）：Agent 建议分区展示
三块并排：`Agent 建议（可折叠原文）` / `规则条款（P-0x 原文）` / `我的处理`。赔付金额旁显示"规则复算值 vs 模型建议值"，差异 >20% 标红。

### 6.5 统一空状态、错误态
每个列表：loading 骨架 + 空状态引导 + 失败可重试；`50002` 弹窗给"切表单"按钮。

## 8. 前端交付标准（自测清单）

- [ ] 三端登录 → 主流程走通，无 4xx 阻塞
- [ ] 订单状态变化能实时刷新（断网重连后能补齐）
- [ ] 金额展示统一"¥x.xx"（分→元，两位小数），费用六项可对
- [ ] 幂等：连点两次"提交"只生成一单（同一 action key）
- [ ] 所有空列表有引导文案，不是白屏
- [ ] 所有失败有可执行下一步（重试/切表单/联系客服）
- [ ] 学生/骑手在 375px 宽度下无横向滚动
- [ ] 敏感信息全脱敏（手机号 `138****0001`）
- [ ] 报价与实付金额一致（同一 `quote_token`/`draft_id` 前后对得上）
- [ ] WS 订阅只订阅自己的 topic；换账号后旧连接已断开
