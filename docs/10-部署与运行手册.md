# 10 · 部署与运行手册

> 目标：**任何人拿到仓库，一条命令起全栈**。这是答辩现场和面试演示的底线。
> 版本 v1.2：表数 22、演示数据 7 单/4 工单、健康检查统一、MinIO 私有、验证 38 条、补 TZ 与压测造数。

---

## 1. 部署单元

| 服务 | 镜像 | 端口 | 数据卷 | 说明 |
|---|---|---|---|---|
| mysql | `mysql:8.0` | 3306 | `./data/mysql` | 初始化脚本自动建库建表 + 演示数据（22 表） |
| redis | `redis:7.2-alpine` | 6379 | `./data/redis` | AOF `everysec`，无密码（仅内网） |
| minio | `minio/minio` | 9000 / 9001 | `./data/minio` | 9001 控制台；**bucket 私有**，应用返回预签名 URL |
| java-app | 自建 `Dockerfile` | 8080 | — | 依赖 mysql/redis/minio；`TZ=Asia/Shanghai` |
| agent-app | 自建 `Dockerfile` | 8000 | `./data/chroma`、`./models` | 挂载模型与向量库；`TZ=Asia/Shanghai` |
| nginx | `nginx:1.25-alpine` | 80 | `./deploy/nginx.conf` | 三端静态 + `/api` 转发 |

**资源建议**：CPU 4 核 / 内存 8G / 磁盘 30G（Chroma 与模型占空间；PyTorch 安装包约 2GB，`bge-small-zh` 权重约 100MB）。

### 2.1 导入后立刻验证（30 秒）

| 步 | 命令 | 预期 |
|---|---|---|
| 1 | `docker compose logs -f mysql \| grep "ready for connections"` | 出现即初始化完成 |
| 2 | `mysql -h127.0.0.1 -uroot -p123456 campus_run < tests/sql/verify-demo-data.sql`（Windows 用 Git Bash/WSL） | **38 行 result 全为 PASS** |
| 3 | `select count(*) from task_order;` | 7 |
| 4 | `select status,count(*) from task_order group by status;` | **6 种状态**（WAITING 2 单，其余各 1） |
| 5 | `select count(*) from ticket;` | 4 |

如果 C20（条款引用）报 FAIL，通常是 `JSON_TABLE` 在 MySQL 8.0.4 以下不可用——本项目要求 8.0+，换镜像即可。

## 3. 启动顺序与命令

| 步骤 | 命令 | 预期 |
|---|---|---|
| 1 | `cp deploy/.env.example deploy/.env`，填 LLM Key、高德 Key | — |
| 2 | `docker compose up -d mysql redis minio` | 三容器 healthy |
| 3 | 等 MySQL 初始化完成（首次 30–60s） | 表与数据就绪 |
| 4 | `docker compose up -d java-app` | `curl localhost:8080/api/common/health` 返回 `code=0` |
| 5 | `docker compose up -d agent-app` | `curl localhost:8000/agent/health` 返回 `status=ok`、`vector_count=10` |
| 6 | `docker compose up -d nginx` | 打开 `http://localhost/student` 出登录页 |

**一键**：`docker compose up -d` 也能起，但首次 java-app 可能在 MySQL 未 ready 时失败（`restart: on-failure` 会自愈，日志有 1–2 次重试属正常）。

**压测前**：`mysql ... < tests/sql/seed-pressure-test.sql`（生成 200 骑手 + 20 单；可重复执行，脚本先清后插）。

## 4. 配置项检查（起不来先查这 8 个）

| # | 项 | 常见错 |
|---|---|---|
| 1 | `SPRING_DATASOURCE_URL` 主机名是否 `mysql`（不是 localhost） | 容器内 localhost 是自己 |
| 2 | `AGENT_TOKEN` 与 `app.agent.token` 是否一致 | 所有工具调用 403 |
| 3 | MinIO bucket 是否已创建且**保持私有** | 预签名失败/图片 403 |
| 4 | `LLM_API_KEY` 是否有效、`LLM_BASE_URL` 是否带 `/v1` | 401 / 404 |
| 5 | `EMBED_MODEL_PATH` 是否挂载到容器内路径 | 启动报找不到模型 |
| 6 | 端口冲突（8080/8000/5173/80） | 起不来但无报错 |
| 7 | `TZ=Asia/Shanghai`（MySQL/Java/Python 三处） | 时间差 8 小时/夜间费算错 |
| 8 | `app.policy.version` 与 `policy_doc.version` 是否一致 | 启动告警（v1.2 起强制校验） |

## 5. 健康检查与自检接口

| 接口 | 用途 | 正常返回 |
|---|---|---|
| `GET /api/common/health` | Java + MySQL + Redis 三连通 | `{code:0, data:{db:"ok", redis:"ok", version}}` |
| `GET /agent/health` | Python + 模型 + 向量库 + 预算 | `{status:"ok", model, vector_count:10, budget_left}` |
| `GET /api/admin/dashboard` | 业务是否活着 | 有今日数据 |

**自检脚本思路（写进手册，不写代码）**：依次请求上述 3 个接口 + 建 1 单 + 抢 1 单，全部成功即环境可用。每次演示前手动走一遍 §7。

## 6. 常见故障排查

| 现象 | 可能原因 | 排查 |
|---|---|---|
| 下单 500，日志 `Cannot connect to Redis` | Redis 未起或 host 错 | `docker compose ps`，`redis-cli ping` |
| 抢单全失败，返回"未上线" | `cr:rider:state` 未初始化/心跳没续期 | 看 `HGETALL cr:rider:state:{id}` 与 TTL |
| 抢单全失败，返回"状态不允许"（Lua 返回 4） | `cr:order:status` 镜像丢失 | 跑重建任务，或回查 MySQL 兜底 |
| 支付后订单仍 `DRAFT` | 回调未触发 | 查 `pay_record`、回调日志；手动重放 |
| 订单详情旧状态 | 缓存未删/延迟双删失效 | 看 `cr:order:detail` 的 `expire_at` |
| 工单无 Agent 建议 | Stream 未消费 / Python 500 | `XLEN cr:stream:ticket`、`XPENDING`、agent 日志 |
| Agent 回复"小助手忙" | 模型超时/key 失效/预算耗尽 | `/agent/health` 看 model 与 `budget_left` |
| 图片 403 | 预签名过期或 bucket 策略错 | 重新调 C-06 换 URL |
| 前端 404 | Nginx 未配 `try_files` | 检查三个 location |
| 骑手大厅空 | GEO 数据为空 | 让骑手上线一次，或跑重建 |
| 时区错乱 | 容器 UTC | 三处都设 `TZ=Asia/Shanghai` |
| 条款版本告警 | 改了 `policy_doc` 没重灌 | A-18 重灌 + 改 `app.policy.version` |

## 7. 演示路线（4 分钟，答辩必背）

| 步 | 操作 | 讲什么 |
|---|---|---|
| 1 | 学生端说"帮我把东门菜鸟驿站的快递拿到5号楼302，五点前" | Agent 追问重量 → 报价卡 → 确认 → 模拟收银台支付 |
| 2 | 切骑手端，两个账号同时点抢单 | 一个成功一个"手慢了"——Lua 原子 + 同步落库 |
| 3 | 骑手取件（取件码）→ 送达 → 学生确认 | 状态时间线实时刷新（WebSocket） |
| 4 | 运营端把订单 7 从 EXCEPTION 改派 | 状态机 `EXCEPTION→WAITING`、旧骑手在手数 -1、决策回放 |
| 5 | 造一单无人抢，等 90s | 首轮扩圈加价 → 第二轮 Agent 决策 → 达上限转人工（`dispatch_paused`） |
| 6 | 学生提交"超时 40 分钟"投诉 | 工单台 10s 后出现定性 + P-04 + 建议 50% + 复算对比 |
| 7 | 运营通过赔付（部分） | `refund_record` 生成，`pay_record` 仍为已支付，结算列表显示扣回 |

**备选**：JMeter 现场跑 200 并发抢单。

## 9. 数据备份与重置

| 操作 | 命令/方式 |
|---|---|
| 备份 | `mysqldump campus_run > backup/$(date +%F).sql`（演示前一天必做） |
| 恢复 | 灌回 SQL 后重启 java-app 清缓存 |
| 重置 | `docker compose down -v && rm -rf ./data && docker compose up -d` |
| 清缓存 | `redis-cli --scan --pattern 'cr:order:*' \| xargs redis-cli del`（仅演示环境） |
| 压测清理 | 重灌 `02-demo-data.sql` 或用 `seed-pressure-test.sql` 的清理段 |

**注意**：不要删 `./data/chroma`，重灌向量库要重新 embedding（1–2 分钟）。

## 10. 部署到公网（可选）

若想给面试官一个可访问链接：2C4G 云服务器 + 域名 + HTTPS（certbot），必须做四件事：
1. `app.jwt.secret` 换随机值，`.env` 不入库
2. `/internal/agent/**` 只允许容器网段访问（Nginx 层拒绝外网）
3. MySQL/Redis 不映射宿主端口
4. MinIO 保持私有 + 预签名有效期 ≤10 分钟

**不做也行**，本地 compose + 录屏对简历项目完全够用。
