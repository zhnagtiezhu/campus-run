# 02 · 数据库设计

> MySQL 8.0 ｜ 库名 `campus_run` ｜ **22 张表**
> **约定**：InnoDB ／ `utf8mb4_general_ci` ／ 主键 `id bigint unsigned auto_increment` ／ 金额统一 `int`（单位：分）／ 时间 `datetime` ／ 坐标 `decimal(10,7)`。
> **三件套约定（v1.2 修正）**：业务主表含 `created_at`、`updated_at`、`delete_flag`；**流水/日志/财务/配置表例外**（`order_status_log`、`grab_record`、`pay_record`、`settlement`、`ticket_event`、`agent_tool_log`、`agent_turn_log`、`agent_message`、`dispatch_decision`、`refund_record`、`rider_credit_log`、`policy_doc`、`campus`、`notify_message` 不设 `delete_flag`），例外必须在建表注释里写明原因。

---

## 1. ER 关系

```
campus 1─n rider
campus 1─n task_order
user 1─n address
user 1─n task_order ─n─1 rider
user 1─n agent_session 1─n agent_message
user 1─n notify_message
task_order 1─n order_status_log
task_order 1─n grab_record
task_order 1─1 pay_record
task_order 1─n refund_record（退单款 / 赔付，一单可多条）
task_order 1─1 settlement
task_order 1─n ticket ─1─n ticket_event
task_order 1─1 review
task_order 1─n dispatch_decision
rider 1─n grab_record
rider 1─n rider_credit_log
refund_record ─n─1 settlement（结算后赔付的冲回依据）
agent_session 1─n agent_tool_log（按 trace_id/session_id 关联）
agent_session 1─n agent_turn_log
policy_doc （独立事实源，同步至 Chroma）
```

关键：**`task_order` 是唯一的事实源头**，所有统计、工单、结算、决策、退款都挂在它下面；**资金的唯一流水是 `pay_record + refund_record`**，`task_order.pay_status` 只是汇总快照。

## 3. 枚举字典（前后端 + Agent 共用，字段值必须一致）

### 3.1 订单状态 `task_order.status`（v1.2 完整迁移矩阵）

| from \ to | WAITING | ACCEPTED | PICKED | DELIVERED | COMPLETED | EXCEPTION | CANCELLED |
|---|---|---|---|---|---|---|---|
| DRAFT | SYSTEM | — | — | — | — | — | USER / SYSTEM |
| WAITING | SYSTEM / AGENT（事件） | RIDER | — | — | — | — | USER / ADMIN |
| ACCEPTED | **ADMIN / AGENT（改派）** | — | RIDER | — | — | RIDER / ADMIN | ADMIN |
| PICKED | — | — | — | RIDER | — | RIDER / ADMIN | ADMIN |
| DELIVERED | — | — | — | — | USER / SYSTEM | USER / SYSTEM | — |
| EXCEPTION | **ADMIN / AGENT（重派）** | — | — | — | ADMIN | — | ADMIN |
| COMPLETED | — | — | — | — | — | — | — |
| CANCELLED | — | — | — | — | — | — | — |

- `COMPLETED`、`CANCELLED` 为终态。
- 同状态"事件"只允许 SYSTEM / AGENT（重派、Agent 加价），USER / RIDER 不可以。
- `ACCEPTED→WAITING` 与 `EXCEPTION→WAITING` 是**改派/重派**专用：必须同时解绑 `rider_id`、旧骑手 `active_order_count-1`、写 `dispatch_decision(REASSIGN)`。
- 支付回调的 `DRAFT→WAITING` 操作者是 **SYSTEM**（v1.1 写成 USER，已修正）。

| type | agent_category | 含义 |
|---|---|---|
| 1 | delay | 超时 |

| 3 | lost | 丢件 |
| 4 | attitude | 态度 |
| 5 | other | 其他 |

> 接口出参统一用 `agent_category` 字符串（可读、便于评测标注），数据库 `ticket.type` 仍存 tinyint；转换只在 Java 的 `TicketConverter` 一处做。

## 5. 一致性设计要点（资金与状态）

1. **状态机是唯一裁判**：统一入口 `OrderStateMachine.requireTransit(from, to, operator)`，任何状态变更必须走它；`UPDATE task_order SET status` 只允许出现在 `OrderService` 的三个方法里。
2. **金额只算一次**：`fee/urgent_fee/night_fee` 在报价时冻结；后续加价只改 `raise_fee`（并同步 `urgency_fee`、`total_fee`），不得改 `fee`。触发封顶时 `total_fee=2000`，`fee = 2000 - urgent_fee - night_fee`，订单展示标 `capped=true`。
3. **加价并发安全**：`UPDATE task_order SET raise_fee=raise_fee+?, urgency_fee=urgency_fee+?, total_fee=total_fee+? WHERE order_no=? AND raise_fee+? <= 500`，影响行数 0 → 40908；单次 >300 直接拒绝。`cr:lock:raise` 只做体验优化。
4. **结算幂等**：`settlement.order_id` 唯一；插入冲突视为已结算。
5. **退款/赔付幂等**：`refund_record.idem_key` 唯一；`pay_record.status` 从 1→3 必须带 `WHERE status=1`；部分退款只新增 `refund_record`，不改 `pay_record.status`。
6. **结算后赔付**：`bear_party=rider` 时写 `refund_record.settlement_id`，结算列表显示"应扣回"，下次结算或运营手动冲销。
7. **信用分**：所有变动写 `rider_credit_log`；日上限靠 `cr:credit:daily:{rider_id}:{yyyymmdd}`；低于 60 在抢单接口实时判断，不改 `rider.status`。
8. **下单幂等**：`task_order.idem_key` + `(user_id, idem_key)` 唯一索引兜底；Redis `cr:idem` 只做 10 分钟快路径。
9. **派单终止**：`dispatch_paused=1` 后必须 `ZREM cr:zset:timeout`，避免 Agent 每 5 秒重复决策。
10. **逻辑删除例外**：`task_order`、`settlement`、`pay_record`、`refund_record` 禁止逻辑删除（财务留痕）。

### 6.1 与 v1.1 的差异（迁移时注意）

| 项 | v1.1 | v1.2 | 原因 |
|---|---|---|---|
| 表数量 | 17 | 22（+refund_record、rider_credit_log、agent_message、agent_turn_log、notify_message） | 让已承诺功能有数据源 |

### 6.2 建表必须遵守的 6 条

1. 金额列一律 `int`，注释写"分"，禁止 `decimal/double`；
2. `task_order.version` 不可省略，所有状态更新必须带它做乐观锁；
3. `settlement.order_id`、`pay_record.order_id`、`review.order_id` 的唯一索引是幂等底座，不可改普通索引；
4. `refund_record.idem_key`、`uk_dd_order_round`、`uk_order_idem` 是 v1.2 新增的幂等约束，不可省；
5. JSON 列只用于数组/对象型字段，不塞查询条件；
6. `agent_tool_log`、`agent_turn_log`、`refund_record`、`rider_credit_log` 只增不改。
