## 5. 核心用例（含异常与验收标准）

### UC-01 表单下单（P0）

- **参与者**：学生
- **前置**：已登录；账户无未支付订单（有则提示先处理）
- **主流程**：
  1. 学生选类别、地图选起止点、填重量/时限/备注/申报价值
  2. 前端调 `quote_price` 展示费用明细（基础/距离/重量/加急/夜间）→ 得到 `quote_token`（15min）
  3. 提交（可带 `idempotency_key`）→ 生成订单 `DRAFT` → 拉起模拟支付
  4. 支付回调（SYSTEM）→ `DRAFT→WAITING`，写延迟队列（+90s）
- **异常**：
  - E1 距离 > 3000m 或超出校区半径 → `40002`，不生成订单
  - E2 命中禁运清单关键词或申报价值 > 500 元 → `40003`/`40007`，返回条款 `P-02`
  - E3 报价与提交时价格不一致（草稿 15min 过期）→ `40004`，重新报价
  - E4 **非服务时段（07:00–23:00 之外）** → `40006`，提示服务时段
  - E5 重复提交（同一 `idempotency_key`）→ 只生成一单，第二次返回首次结果（`code=0`）
- **验收**：学生下单后 1s 内大厅可见；费用明细六项可核对；`declared_value>50000` 被拒。

### UC-02 抢单（P0）

- **参与者**：骑手
- **前置**：已上线；在手单 < 3；信用分 ≥ 60；订单 `WAITING`
- **主流程**：
  1. WebSocket 收到新任务推送（含距离、价格）
  2. 点击抢单 → `RateLimiter` → Lua 原子校验并占位（order grab key + 骑手在手数）
  3. **同步执行** `UPDATE task_order SET rider_id=?, status='ACCEPTED' WHERE status='WAITING' AND rider_id IS NULL`
  4. 影响行数 1 → 返回成功；`XADD cr:stream:dispatch GRABBED` 异步做通知与 `grab_record` 落库
  5. 推送学生端状态变更
- **异常**：
  - E1 已被他人抢 → `40902` + `FAIL_GONE`，前端提示"手慢了"
  - E2 骑手手上有单已满 → `40903` + `FAIL_BUSY`
  - E3 未上线/未审核 → `40906` + `FAIL_OFFLINE`
  - E4 信用分 <60 → `40906` + `FAIL_CREDIT`
  - E5 同一骑手重复抢同一单 → 返回幂等成功（`FAIL_DUPLICATE` 只记日志，不报错）
  - E6 Redis 成功但 DB 影响行数 0 → **同步回滚** grab key + `HINCRBY -1`，返回 `40901`/`40902`
- **验收**：200 并发抢同一单，MySQL 中 `rider_id` 唯一绑定，`grab_record` 仅 1 条 SUCCESS，接口成功数 = 1。

### UC-03 派单超时与升级（P1）

- **前置**：订单 `WAITING` 且 `dispatch_paused=0`，超过 90s
- **主流程**：
  1. `DispatchTimeoutTask`（5s 轮询）从 `cr:zset:timeout` 捞到期订单
  2. 第 1 次超时：扩圈 3000m + `raise_fee+100`，`dispatch_round=2`，重推 + `ZADD(+90s)`
  3. 第 2 次超时：调 `POST /agent/dispatch/decide`，`dispatch_round=3`
  4. Agent 返回 `DispatchDecision`；Java 阈值校验 → 执行（改派/加价）或建工单
  5. `ESCALATE_CS` 或 `raise_fee` 达 500 → 建工单 + `dispatch_paused=1` + `ZREM`，不再自动重派
- **异常**：Agent 超时 8s 或置信度 <0.6 → 建工单转人工，不阻塞
- **验收**：造 10 单无人抢场景，Agent 决策全部落在阈值内；订单不会被重复决策（`uk_dd_order_round`）；`dispatch_paused=1` 后不再产生新决策。

### UC-04 售后工单（P1）

- **参与者**：学生 / 骑手 / 系统
- **主流程**：
  1. 学生提交售后（类型 + 描述 + 凭证）
  2. Java 建 `ticket`（`source=USER`），预计算 `evidence_count`/`signed_at`/`within_window`，发 `cr:stream:ticket`
  3. Python 消费 → ServiceAgent 检索规则库 → 产出 `TicketAssessment`（含 `damage_level`）
  4. 回写 `ticket.agent_*` 字段，状态 `REVIEWING`
  5. 运营在工单台看到建议 + 条款引用 + Java 复算金额 → 通过/驳回 → 通过则写 `refund_record`（运营 token）
- **异常**：
  - E1 RAG 无命中 → `liable_party=unknown`，不给赔付建议，直接转人工
  - E2 建议赔付 > 1000 分 → 前端强标记"高额，需主管（role=2）"
  - E3 条款编号不在本轮检索结果中 → 丢弃该条款并降置信度
  - E4 超出 2 小时受理窗口 → `within_window=0`，Agent 必须判 `user` 或 `unknown`，不得给赔付
- **验收**：20 条真实话术样本，条款引用正确率 100%；赔付金额与 `RefundRuleEngine` 复算一致（±20% 内）。

### UC-05 自然语言下单（P1）

- **主流程**：
  1. 学生输入"下午五点前帮我把菜鸟驿站快递拿到 5 号楼 302"
  2. OrderAgent 抽取槽位：category=1、from=菜鸟驿站、to=5号楼302、deadline=17:00；缺 `weight` 用默认 1kg
  3. 一次只问一个缺失槽位（最多 3 轮）
  4. 槽位齐全 → 调 `quote_price` → 调 `create_order_draft` → 返回报价卡片（含 `quote_token` + `draft_id`）→ 用户点"确认下单"
  5. 前端带 `draft_id` 调 U-08（幂等），**支付不经 Agent**
- **异常**：
  - E1 3 轮后仍缺关键槽位 → 返回表单预填链接
  - E2 地址无法定位 → 反问"附近地标"，最多 2 次 → 转表单
  - E3 用户改口（"算了改成送到宿舍楼下"）→ 覆盖槽位不丢上下文
  - E4 类目默认起点（快递→菜鸟驿站、餐→一食堂、打印→打印店）只在用户未给起点时使用，且回复必须说明"默认从 XX 取"
- **验收**：20 条样本 ≥17 条一次成型；不得自行编造价格与时间。

### UC-06 改派 / 重派（P1）

- **参与者**：运营 / DispatchAgent
- **主流程**：
  1. 订单处于 `ACCEPTED` 或 `EXCEPTION`
  2. 运营 A-05 或 Agent `reassign_order` 指定新骑手
  3. Java 校验新骑手在线、在手 <3、信用 ≥60
  4. 状态机 `ACCEPTED/EXCEPTION → WAITING`（操作者 ADMIN/AGENT），解绑旧骑手、旧骑手在手数 -1、删 grab key
  5. 新骑手抢单（或 Dispatch 直接绑定）→ `WAITING → ACCEPTED`
  6. 写 `dispatch_decision(REASSIGN)` + 状态流水
- **异常**：新骑手不可用 → 40906；订单已取消 → 40901
- **验收**：改派后旧骑手在手数正确、学生端状态推送、`dispatch_decision` 可回放。

### UC-07 自动确认收货（P1）

- **前置**：订单 `DELIVERED` 超过 30 分钟，用户未确认且无工单
- **主流程**：`AutoConfirmTask` 每分钟扫描 → `DELIVERED→COMPLETED`（SYSTEM）→ 触发结算 + 骑手准时信用分
- **异常**：存在未完结工单 → 暂不自动确认，等工单处理
- **验收**：造 31 分钟前的 DELIVERED 单，1 分钟内变 COMPLETED 且有结算单。

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 订单详情缓存命中 P99 < 30ms；抢单接口 P99 < 100ms（200 并发） |
| 可用性 | Agent 服务不可用时，主流程成功率不受影响（降级验证） |
| 一致性 | 订单状态只允许状态机定义的迁移；并发修改用 `version` 乐观锁；抢单"接口成功 = DB 已落库"（v1.2 同步，无最终一致窗口） |
| 安全 | 密码 BCrypt；手机号/身份证/学号加密存储 + 脱敏展示；内部工具接口仅内网 + token；工具只能访问会话所属用户数据 |
| 可观测 | 全链路 `trace_id`；Agent 工具调用 100% 落 `agent_tool_log`，模型调用 100% 落 `agent_turn_log` |
| 可复现 | `docker compose up -d` 一条命令起全栈；演示数据由初始化脚本导入；38 条断言全 PASS |
