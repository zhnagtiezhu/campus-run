## 2. 一页速查（不想读全文就看这个）

| 问题 | 答案 |
|---|---|
| 业务是什么 | 校园代取快递/代买餐/代打印/代还书，三端（学生/骑手/运营） |
| Java 管什么 | 订单状态机、计价、支付、结算、退款/赔付、确定性派单、工单 |
| Redis 管什么 | 抢单闸门（Lua）、GEO 圈人、Stream、ZSet 延迟队列、缓存三件套、限流、幂等、状态镜像 |
| Python 管什么 | 自然语言下单、进度/FAQ 问答、超时派单决策、售后工单初判 |
| 谁写数据库 | **只有 Java**，Python 走内部工具 API（14 个） |
| Agent 挂了会怎样 | 主流程照跑，前端切表单模式 |
| 抢单怎么保证不超卖 | Lua 原子占位（含同骑手幂等）+ **同步条件 UPDATE** + 失败回滚 |
| 赔付款谁算 | Java 按规则库费率公式复算，模型只输出定性 + 损坏等级 |
| 退款和赔付怎么记 | `refund_record` 两条流水（ORDER_REFUND / COMPENSATION），部分赔付不改支付状态 |
| 单校区怎么体现 | `campus` 表一条记录，GEO key 不分区，跨区逻辑预留不实现 |
| 前端怎么跑 | Vue3 + Element Plus + 高德 JS，三端同仓分目录，Nginx 三路径 |
| 多久能做完 | 8 周课余约 120h；M2（第 5 周）就能投简历 |
| 有多少代码量 | 预计 Java ~7k 行、Python ~2.5k 行、Vue ~5k 行、SQL ~1.2k 行 |

## 3. 12 个必须记住的数值（代码里写错就对不上文档）

| 项 | 值 |
|---|---|
| 起步价 | 300 分（≤1000m 且 ≤2kg） |
| 距离加价 | 每 500m +50 分 |
| 重量加价 | 每 1kg +100 分 |
| 加急 / 夜间 | +200 / +100 分（分别入 `urgent_fee` / `night_fee`） |
| 单笔封顶 | 2000 分（不含后续加价） |
| 抽佣 | 实付 10%，最低 30 分 |
| 首轮派单 | 1500m，等 90s |
| 次轮 | 3000m，`raise_fee` +100，再等 90s |
| 骑手在手单上限 | 3 单 |
| 加价阈值 | 单次 ≤300，累计 ≤500（只算 `raise_fee`） |
| 高额赔付需复核 | >1000 分（role=2） |
| Agent 置信度转人工 | <0.6（决策）/ <0.7（意图） |

## 4. 文档之间的对应关系（避免改了一处忘另一处）

```
00 参数阈值
 ├─→ 01 用例验收标准
 ├─→ 02 表字段、枚举、状态机、费用拆分、退款模型
 ├─→ 03 接口出参与错误码
 ├─→ 05 Redis key 与限流值
 └─→ 06 Agent 阈值与赔付规则
        └─→ 附件 规则库条款（P-01~P-10, v1.1）

02 枚举字典 ─→ 03 错误码 ─→ 08 ErrorCode 枚举 ─→ 07 TS 类型
06 RAG 切块 ─→ 附件 条款结构 ─→ 02 policy_doc 表 ─→ 03 list_policy_docs
12 WBS 每一步 ─→ build/Sxx 施工图 ─→ 09 用例编号（验收）
```

**改动规则**：任何阈值、字段、枚举变更，必须同步更新"文档 + SQL + 测试 + 施工图"四处，否则文档就失去价值。
