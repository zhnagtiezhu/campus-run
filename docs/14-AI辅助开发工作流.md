# 14 · AI 辅助开发工作流

> 目标：让"用 AI 从零写这个项目"变成**可重复的流水线**，而不是每次凭感觉提问。
> 配套：`08-工程规范.md`（人写代码的规则）、`build/`（每一步的施工图）。
> 版本 v1.2（2026-11-17）。

---

## 1. 核心原则

1. **文档是唯一输入**：每次投喂 AI 的内容必须来自 `docs/` 与 `build/`，不要口头描述。
2. **一步一验收**：AI 产出的每一步必须能通过该步的验收命令（编译 / 单测 / Postman / SQL 断言）才进入下一步。
3. **先契约后实现**：接口签名、表字段、状态机、错误码先定死（`02`/`03`），再让 AI 填实现。
4. **domain 先写**：纯函数（计价、状态机、退款规则）没有框架依赖，AI 最不容易写错，还能用测试兜底。
5. **数字不交给 AI 编**：压测与评测数字必须自己跑，AI 只负责生成脚本与报告模板。

---

## 2. 仓库根 `AGENTS.md`（开工第一天就建）

把 `08` 的铁律压成 10 条，放在仓库根，每次让 AI 写代码前先让它读：

```markdown
# campus-run 编码铁律（AI 必须遵守）

1. JSON/HTTP/DB 字段一律 snake_case；Java 内部类用大驼峰。
2. 金额一律 int（分）；禁止 double/BigDecimal 参与计算。
3. 费用必须拆成 fee/urgent_fee/night_fee/raise_fee/urgency_fee/total_fee 六字段。
4. 订单状态只能走 OrderStateMachine.requireTransit(...)；禁止直接 UPDATE status。
5. Redis 写操作必须带 TTL，key 必须在 docs/05 的 key 表里。
6. 事务方法内禁止 Redis/HTTP/Stream 调用（放 afterCommit）。
7. 写接口必须支持 Idempotency-Key；key 按"用户动作"生成。
8. Agent 工具不注册 refund_order / update_order_status；工具用户身份从 X-Session-Id 派生。
9. 错误码只能来自 ErrorCode 枚举（docs/03 §9），禁止硬编码数字。
10. 每次改动必须同步 docs/02、docs/03、SQL、测试四处中的相关项。
```

> 如果你的 AI 工具支持项目级指令（如 `AGENTS.md` / `CLAUDE.md` / `.cursorrules`），直接用这个文件；不支持就在每次 Prompt 开头贴一遍。

## 3. 五层生成顺序（不要跳）

```
L0 契约：枚举 / ErrorCode / DDL / 接口签名（人写或人审）
L1 领域：OrderStateMachine / PriceCalculator / RefundRuleEngine / RiderScore（纯函数）
L2 持久：Entity / Mapper / DTO / VO（与 02 对齐）
L3 编排：Service（事务、幂等、状态机调用）
L4 接入：Controller / 拦截器 / WS / 定时任务 / 内部工具
L5 前端：types → api → store → 页面 → 组件
```

每一层的"完成"标准：
- L0：`mvn compile` 过、SQL 能建表、`verify` 38 条 PASS
- L1：`mvn test` 中 domain 测试全绿
- L2：`mvn compile` + 一个 Mapper 的简单查询能跑通
- L3：对应的 T-xx 用例能手工调通
- L4：Postman 对应请求绿
- L5：页面能走通、375px 不横向滚动

## 4. 每一步怎么投喂（Prompt 模板）

### 4.1 通用模板

```text
你是本项目的 Java/Python 开发。先读：
- docs/08-工程规范.md（铁律与目录）
- docs/02-数据库设计.md 的「<表名>」一节
- docs/03-接口设计.md 的「<接口编号>」
- build/<Sxx-xxx>.md（本步施工图）
- 仓库根 AGENTS.md

本步只做：<一句话目标>
产出文件：<施工图里的清单>
必须满足：<施工图里的契约 3–6 条>
禁止：<施工图里的禁止事项>
验收：<施工图里的命令/用例>

请先输出"实现计划 + 文件清单"，我确认后再写代码。
每次只写一个文件；写完告诉我该跑哪条命令。
```

### 4.2 关键技巧

| 技巧 | 说明 |
|---|---|
| 先要计划再要代码 | 让 AI 列文件清单与依赖顺序，能提前发现它想"自创接口" |
| 一次一个文件 | 大段代码最容易漏校验、漏事务、漏 snake_case |
| 贴"反例" | 例如"不要写 `BigDecimal`，不要 `@Transactional` 里发 HTTP" |
| 让它自查 | 写完要求它对照 `08` §11 自检清单逐条打勾 |
| 失败就缩小 | 编译错先让它只修错误，不要顺手重构 |
| 版本锁定 | 依赖版本只从 `04` §5 取，禁止让 AI "升级到最新" |
| 不喂全库 | 只喂相关文档片段；全库会让它抓错重点 |

## 5. 验收四件套（每步都跑）

| # | 命令 | 通过标准 |
|---|---|---|
| 1 | `mvn -q test` / `python -m compileall app` | 编译 + 单测绿 |
| 2 | Postman 对应 folder | 相关请求全绿 |
| 3 | `git diff` 人工过一遍 | 无 camelCase、无 double、无硬编码错误码、无绕过状态机 |
| 4 | 对照 `08` §11 自检清单 | 10 条逐项勾选 |

> 第 3 步不能省。AI 最容易在这四个地方"看起来对、其实错"：字段命名、金额类型、状态机入口、Redis TTL。

## 6. AI 常见 8 个错误（按出现频率）

| # | 错误 | 怎么发现 | 怎么防 |
|---|---|---|---|
| 1 | 把 `snake_case` 写成 camelCase | 看 JSON 字段/DB 列 | `JacksonConfig` + 自检清单 |
| 2 | 金额用 `double`/`BigDecimal` | grep `double\|BigDecimal` | 铁律 2 + 只允许 `int` |
| 3 | 直接 `UPDATE task_order SET status` | grep `set status` | 铁律 4 + 只允许 OrderService 三处 |
| 4 | Redis 写入没 TTL | grep `opsForValue().set` | 铁律 5 + key 表对照 |
| 5 | 在 `@Transactional` 里发 HTTP/写 Redis | 看 Service 方法 | 铁律 6 + afterCommit |
| 6 | 幂等 key 每次请求新生成 | 看前端拦截器 | 铁律 7 + `useIdemKey` |
| 7 | 自创接口/字段（文档里没有） | diff 对照 `03` | 先给文件清单再写代码 |
| 8 | 把 `user_id` 当工具入参 | 看 registry | 铁律 8 + 从 session 派生 |

## 7. 上下文管理

| 问题 | 做法 |
|---|---|
| 会话太长开始跑偏 | 一个功能一个会话；超过 ~20 轮就重开，把当前文件与失败日志带上 |
| AI 忘了前面的约定 | 每轮开头重贴 `AGENTS.md` 的 10 条 + 本步验收命令 |
| 改了 A 文件影响 B | 只喂相关文件，不要全仓库；让它先 grep 引用 |
| 需要"记忆" | 用 `build/00-进度表.md` 记录已完成步骤与遗留问题，每轮贴给它 |

---

## 8. 与 `build/` 的关系

- `build/` 是**施工图**：每一步的文件清单、契约、禁止事项、验收命令、可复制 Prompt。
- 顺序：`S00 环境` → `S01 骨架` → `S02 领域` → … → `S16 收尾`。
- 每步开头都有"前置"和"完成后可进入下一步"的判定；不满足就不要往下走。
- 施工图与设计文档冲突时，**以设计文档为准**，并回头改施工图（改一处记一处）。

## 9. 一个完整的例子（领域层）

```text
你只做一件事：实现 com.campusrun.domain.PriceCalculator。

输入：
- backend-java/src/test/java/com/campusrun/domain/PriceCalculatorTest.java（契约，不可改）
- docs/00 §4.1（计价规则）
- docs/02 §5.2（费用六字段口径）
- docs/08 §1（domain 包禁止依赖 Spring/Mapper/Redis）

要求：
1. public static FeeDetail calculate(int distanceM, double weightKg, boolean urgent, LocalDateTime orderAt)
2. record FeeDetail(int baseFee, int distanceFee, int weightFee, int urgentFee, int nightFee, int total, boolean capped)
3. 金额全 int；距离/重量向上取整；夜间 21:00–06:00；封顶 2000 且 capped=true
4. 不新增依赖、不引入 Spring、不写 main

验收：mvn -q -Dtest=PriceCalculatorTest test 全绿。
写完只输出：文件路径 + 测试结果 + 你对边界的两条说明。
```
