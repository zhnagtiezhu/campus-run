# S09 · 结算、退款与信用分

## 1. 目标
订单完成后 T+0 结算；取消/工单赔付走统一 `refund_record`；信用分有流水、有日上限；30 分钟自动确认。

## 2. 前置
S08 状态机与改派可用。

## 4. 契约

**结算（COMPLETED 触发）**
```
platform_fee = max(floor(total_fee * 0.10), 30)
rider_income = total_fee - platform_fee
INSERT settlement(order_id UNIQUE, rider_id, order_amount, platform_fee, rider_income, status=1, settled_at=now)
```
- 唯一冲突 = 已结算，直接返回；
- 锁 `cr:lock:settle` 10s（双保险）；
- 触发点：U-14 确认、AutoConfirmTask、运营异常单完成。

**退款/赔付（唯一入口 RefundService）**
```
create(type, order_id, ticket_id?, amount, bear_party, idem_key)：
  1) 校验 amount>0；累加不超订单金额+赔付上限（由调用方算）
  2) INSERT refund_record(status=0, idem_key UNIQUE)；冲突→返回已有记录（幂等）
  3) 锁 cr:lock:refund 10s
  4) 模拟退款：成功→status=1, refunded_at=now；失败→status=2（重试任务捡起）
  5) 若是 ORDER_REFUND 且金额=total_fee：pay_record WHERE status=1 → 3；order.pay_status=2
     若部分：pay_record 不变；order.pay_status 不变
  6) afterCommit：清详情缓存、WS、notify_message
```
- `bear_party=rider` 且订单已结算：写 `settlement_id`，结算列表显示"应扣回"。

**U-13 WAITING 取消**：状态 `WAITING→CANCELLED(USER)` + `create(ORDER_REFUND,total_fee,platform)`。
**A-04 强制取消**：同上，操作者 ADMIN。
**A-09 credit**：`delta` + 写 `rider_credit_log` + 更新 `rider.credit_score`。
> 工单的 A-13 resolve / A-14 reject 在 **S10** 实现（工单先于本步存在），调用本步的 `RefundService.create(COMPENSATION, ...)`；不要把工单控制器写进 S09。

**信用分规则（唯一入口 CreditService）**
| 场景 | delta | reason_code | 触发 |
|---|---|---|---|
| 准时送达 | +2（当日累计 ≤10） | ON_TIME | 订单 COMPLETED 且 `delivered_at <= expect_deadline` |
| 超时 >30min | −5 | TIMEOUT | `delivered_at > expect_deadline + 30min` |
| 投诉成立 | −10 | COMPLAINT | 工单 RESOLVED 且 `agent_liable_party=rider` |
| 运营调整 | 任意 | ADMIN_ADJUST | A-09 |

日上限：`INCRBY cr:credit:daily:{riderId}:{yyyyMMdd}`，返回 >10 时不再加分（但仍写流水 delta=0？不写）。
低于 60：不改 `rider.status`，抢单接口返回 40906。

**R-12/R-13/R-14（RiderIncomeController，本人数据）**
```
R-12 GET /api/rider/income/summary?date_from=&date_to=
     → 总收益 SUM(settlement.rider_income)、完成单量、抽佣合计、赔付扣回 SUM(refund bear_party='rider')
R-13 GET /api/rider/income/page?page=&size=  → settlement 分页（含订单号、金额、状态、settled_at）
R-14 GET /api/rider/credit/page?page=&size=  → rider_credit_log 分页（reason_code/delta/score_after/created_at）
```

**AutoConfirmTask**：每分钟
```
SELECT id FROM task_order
WHERE status='DELIVERED' AND delivered_at < now-30min
  AND NOT EXISTS (open ticket: status IN ('PENDING','REVIEWING'))
→ DELIVERED→COMPLETED(SYSTEM) + 结算 + 信用分 + 通知
```

## 5. 实现要点
1. 所有金额计算在 Java（`RefundRuleEngine` + 封顶），**调用方必须传已复算金额**，RefundService 只做记账与执行。
2. 退款状态机：0→1/2；重试任务只捡 status=0 且 created_at<1min。
3. 结算与退款都要 `afterCommit` 才发 WS/消息。
4. 信用分变动与业务在同一事务；日上限 Redis 计数在事务内（允许失败回滚导致计数多 1，可接受）。
5. A-20 结算列表带 `refund_record` 的扣回金额（`SUM(bear_party='rider' AND settlement_id=...)`）。

## 6. 禁止
- 不要用 `pay_record.status=2` 表示部分退款。
- 不要重复插入 settlement/refund（必须唯一索引 + 幂等 key）。
- 不要在 AutoConfirm 时跳过"未完结工单"判断。
- 不要让退款金额由前端/模型直接决定。

