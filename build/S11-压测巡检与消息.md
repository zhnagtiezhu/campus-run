## 4. 契约

**ConsistencyCheckTask（每分钟）**
| 校验 | 动作 |
|---|---|
| `cr:order:status` vs MySQL（TOP 50 活跃） | 不一致 → 删缓存 + HSET 正确值 |
| `cr:order:grab:*` 存在但订单无骑手 | DEL key + 告警 |
| `COMPLETED` 无 settlement | 补生成 |
| `DRAFT` 超 15 分钟 | 关闭（S05 已有，合并） |
| `DELIVERED` 超 30 分钟无未完结工单 | 自动确认（S09 已有，合并） |
| `ticket PENDING` 超 10 分钟未初判 | 标 `agent_failed=1` |
| `rider.active_order_count` vs 实际在手 | 修正 + 告警 |
| 布隆/状态镜像缺失 | 重建（`BloomRebuildTask` 扫近 30 天订单） |

**限流（固定窗口 Lua）**
```
local c = redis.call('INCR', KEYS[1])
if c == 1 then redis.call('EXPIRE', KEYS[1], ARGV[1]) end
if c > tonumber(ARGV[2]) then return 0 end
return 1
```
场景与阈值按 `05` §8：login 5/min/IP、quote 10/min/user、order 3/min/user、grab 20/10min/rider、chat 20/10min/session、tool 10/10s/session。
超限 → 42901（grab 用 42902 并写 `cr:alert:grab`）。

**消息**
- `notify_message` 落库 + WS 推送；`notify_user` 工具（S12 接）只走模板。
- C-08/C-09 已在 S03；本步补"订单状态变更/工单处理/信用分变动"三类模板。

**压测**
1. `mysql < tests/sql/seed-pressure-test.sql`（200 骑手 + 20 单）；
2. 用 200 个骑手账号登录并上线（或 `build/S11` 附的 warmup 脚本，写 Redis state + GEO）；
3. JMeter 场景 A（200 并发抢 1 单）、B（缓存前后）、C（改 `expire_at`）；
4. 输出 `docs/压测报告.md` 三张表。

## 5. 实现要点
1. 巡检任务之间用 `@Scheduled(fixedDelay)` 错峰，避免同一秒打满 DB。
2. 修正类操作必须幂等（条件更新），且每次写一条 WARN 日志（带 order_no）。
3. 限流拦截器只对写接口与登录/报价生效；读接口不限。
4. 消息落库后 `afterCommit` 推 WS；离线用户上线用 C-08 拉。
5. 压测前备份演示库；压测后按 seed 脚本尾部清理。

## 6. 禁止
- 不要在巡检里做全表扫描（必须带索引/limit）。
- 不要把限流做成"每个请求都 SET"（用 Lua 原子）。
- 不要给压测账号手动改 `credit_score` 以外的数据。
- 不要把压测数据留在演示库。
