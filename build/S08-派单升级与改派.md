## 4. 契约

**DispatchTimeoutTask（每 5s）**
```
members = ZRANGEBYSCORE cr:zset:timeout 0 now LIMIT 0 20
for order_no in members:
    if status != WAITING or dispatch_paused=1: ZREM; continue
    if dispatch_round == 1:
        raiseFee(order_no, 100, "ROUND2")   // 单次≤300、累计≤500
        dispatch_round=2; ZADD(now+90)
    elif dispatch_round == 2:
        decision = DispatchAgentClient.decide(...)   // 本步固定 ESCALATE_CS
        apply(decision); dispatch_round=3
    else:
        escalate(order_no)   // 建工单 + paused=1 + ZREM
```

**raiseFee**（唯一入口，A-06/add_urgency_fee 共用）
```
UPDATE task_order
SET raise_fee=raise_fee+?, urgency_fee=urgency_fee+?, total_fee=total_fee+?, version=version+1
WHERE order_no=? AND status='WAITING' AND raise_fee+? <= 500
```
- 影响 0 行 → 40908（累计超限）
- 单次 >300 → 40008
- 成功后写状态流水 `WAITING→WAITING/AGENT|SYSTEM`，remark=`RAISE_FEE:{delta}`
- `afterCommit`: 更新 `cr:order:status`、删详情缓存、XADD、WS

**A-04 强制取消**：`WAITING/ACCEPTED/PICKED → CANCELLED(ADMIN)`；`paused=1`；ZREM；退款由 S09 的 RefundService 执行（本步先留接口）。

**A-05 改派**：
1. 新骑手校验：在线、在手<3、信用≥60、`rider_id != 旧`；
2. `ACCEPTED/EXCEPTION → WAITING`（ADMIN/AGENT）；
3. 旧骑手 `active_order_count-1`、`cr:rider:state busy-1`、`DEL grab key`；
4. `dispatch_round=2`、`dispatch_paused=0`、ZADD(now+90)；
5. 写 `dispatch_decision(REASSIGN, applied=1)` + 状态流水。
> 顺序：先状态机迁移（解绑 rider_id），再计数回退；全程事务，Redis 在 afterCommit。

**A-06 加价**：调 `raiseFee`，`role=2` 才允许累计超 500 的单次追加（仍不可 >500，超额需工单审批）。

## 5. 实现要点
1. ZSet 消费必须"先处理再 ZREM"，异常时不要 ZREM（下次重试）。
2. 同一订单可能被多个任务实例处理：`SET NX cr:lock:dispatch:{no}` 5s 或依赖状态条件更新。
3. `dispatch_decision` 用 `(order_id, round)` 唯一索引，重复决策 insert 冲突即跳过。
4. 改派/取消后必须清 `cr:order:detail` 与 `cr:order:status`。
5. 建工单时写 `ticket_event(CREATE, SYSTEM)`。

## 6. 禁止
- 不要在任务里直接 `UPDATE ... SET status`（必须走状态机）。
- 不要忘记 `paused=1 + ZREM`（否则每 5s 重复决策、烧 token）。
- 不要在改派时忘记旧骑手在手数 -1。
- 不要让 `raise_fee` 与 `urgency_fee` 不同步。
